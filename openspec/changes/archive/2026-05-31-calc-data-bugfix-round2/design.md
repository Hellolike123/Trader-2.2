## Context

第二轮扫描发现 19 个计算和数据 bug。假跌破判定是最严重的，直接影响止损机制。其他问题影响置信度连续性、权重归一化、筹码分布等。

## Goals / Non-Goals

**Goals:**
- 修复全部 19 个 bug
- 确保所有修复有测试覆盖

**Non-Goals:**
- 不重构架构
- 不新增功能

## Decisions

### 1. 假跌破判定：改比较对象

**问题**：`_fake_break` 检查 `prev_close >= support`，应为 `prev_close >= hard_stop`。

**决策**：改为 `prev_close >= hard_stop`。

**理由**：
- 假跌破的定义是"跌破止损位后收回"，所以应该检查是否曾高于止损位
- support 是支撑位，高于止损位，检查 support 太宽松

### 2. 置信度门限：60 → 50

**问题**：最大理论置信度 ~73.5，门限 60 导致很多合法转换被拦截。

**决策**：门限降到 50。

**理由**：
- 50/73.5 ≈ 68%，合理
- 仍能过滤低置信度噪声

### 3. confirm_buffer 下限

**问题**：累积乘法可能让 confirm_buffer 接近 0。

**决策**：clamp 到 `[0.5, 2.0]`。

**理由**：
- 0.5 = 确认价比阻力位高 50%（极端宽松）
- 2.0 = 确认价比阻力位高 200%（极端严格）
- 正常范围在 0.8-1.3

### 4. HMM 混合：乘法调整 → 真混合

**问题**：`base * 0.5 + base * hmm_adj * 0.5` 是乘法调整，不是真混合。

**决策**：改为 `base * 0.5 + hmm_target * 0.5`，其中 `hmm_target` 是 HMM 推荐的中性值。

**理由**：
- 真混合能确保 HMM 有足够的纠偏力
- 当校准值远离 1.0 时，HMM 能把它拉回来

## Risks / Trade-offs

**风险 1**：假跌破判定收紧后，可能有些边缘场景从"防守观察"变成"风险回避"
→ 缓解：这是正确的方向，之前太宽松

**风险 2**：置信度门限降低后，阶段转换更频繁
→ 缓解：仍有四层防护机制兜底
