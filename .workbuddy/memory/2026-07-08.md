## 压力位「中短长同一压力」问题修复（P0 级 bug，非算法设计问题）

### 现象
用户跑 skill 时发现 📍买卖点里 短线/中线/长线压力 三档都显示同一值（如 98.04），且另一个 agent 误判为「算法设计问题，不是 bug」。

### 根因（实测代码确认，确为 bug）
`structure_core.py::_find_level_with_touches`（结构_core L882-948）判定「价位是否被突破」时**用错了序列**：
- 压力位（`find_support=False`）误用 `opposite = window_lows`（最低价序列）判突破；
- 支撑位（`find_support=True`）误用 `opposite = window_highs`（最高价序列）判跌破；
- 且用「30% 计数阈值」过松。
导致已被突破的价位（如 98 触及 2 次后涨到 115）仍被当成有效压力返回，未 fallback 到周期最高价。

### 修复（方案 A + B 都做）
1. **方案 A（structure_core.py）**：突破/跌破判定改用正确序列——压力用 `max(window_highs) <= price*1.03`、支撑用 `min(window_lows) >= price*0.97` 判定「未破」。被突破的价位会被拒，触发 fallback 到周期最高/最低价（即真实高位/低位）。
2. **方案 B（run_analysis.py 渲染循环）**：支撑循环(L1969)与压力循环(L1978)增加 1.5% 容差去重，中/长线算出同一压力时只渲染一行（与既有 exit_plan 去重逻辑一致）。

### 验证
- 新增回归测试 `test_broken_resistance_falls_back_to_window_high`（test_structure_core.py）：构造「98 触 2 次→突破至 117→回落」场景，断言 `short_resist≈98` 且 `mid/long_resist > 105`。
- `test_structure_core.py` 30 passed；`test_fusion_integration.py` 11 passed；`run_analysis.py` / `structure_core.py` py_compile 通过。
- 方案 B 用临时脚本复刻渲染循环验证：现价 95 时输出「短线压力 98 / 中线压力 117」，长线重复行被合并。
