# PRD: trader 输出格式重构 (2026-06-02)

## 1. 目标
重构 `trader` 命令（`run_analysis.py`）生成的分析报告输出格式，使其严格对齐用户最新设计的精简版模板。新版本去除了冗余的调试信息和中间计算状态，增加了更加清晰直接的买卖点指引，并在“主力筹码”模块中新增了动态的“筹码搬家”监测（对比昨日变化并得出结论）。

## 2. 目标输出格式样板（严格遵守）

输出必须严格遵循以下结构和标题，不能使用 Markdown 表格、水平线 `---` 或 `###` 级标题（使用 Emoji + 纯文本作为版块标题）。

```text
分析报告 — 南网科技（688248）

现价：58.50元（-3.50%）
MA5：59.05｜MA10：60.58｜MA20：61.02｜MA30：59.85
ATR 3.69（6.1%）波幅偏高

📊 蓄势期 + 转弱 → 低吸高抛

📍 买卖点
  55.57 止损
  57.61 ← 买 10%（缩量企稳）
  58.50 当前
  59.22 → 卖 33%（阻力位）
  62.85 → 卖 33%（1R 目标）
  62.87 压力
  阶段转派发 → 清仓

💡 为什么这么操作
  阶段：蓄势期（区间震荡，低吸高抛）
  趋势：短期偏弱（价格在 59.00 下方），不追

📌 如果你有持仓（成本 60.00）
  现在：持有，不加仓（亏 2.5%）
  反弹到 60.00：减 50%（保本）
  跌破 55.57：止损（认亏）

🔍 主力筹码
  筹码峰：
    57.88（支撑）｜ 占比 5.91%
    60.46（强阻力）｜ 占比 6.99%
    63.05（弱阻力）｜ 占比 5.29%
  当前价以上：67.3%
  中位数价格：60.29

  筹码变化（对比昨天）：
    57.88（支撑）：5.91% → 4.50%（-24%）← 底部筹码减少
    60.46（强阻力）：6.99% → 8.50%（+22%）← 顶部筹码增加
    结论：筹码在搬家，主力在出货

📊 五层打分
  结构75/量价45｜筹码50｜动能50
  缠论：回调段。一类买、二类买
  威科夫：无明显威科夫信号

🎯 信号判断
  偏多：✓ 结构（两次接近位置止跌）
  警惕：! 量价（午后缩量）  ! 筹码（上方成交密集区）

✅ 亮点：58.50 仍站在防守位 57.61 上方
⚠️ 风险：筹码在搬家，主力在出货，警惕继续下跌
```

## 3. 具体修改要求

1. **核心逻辑：将 EXPMA 纳入支撑/压力候选池 (新增)**:
   - 目标文件：`02-共享模块-shared/trader_shared/structure_core.py` (重点函数 `build_structure_context`)。
   - 需求：目前 `build_structure_context` 中的候选池仅包含 MA、5日高低点和20日高低点。请先通过 `calc_expma` (在 `momentum_core.py` 中) 或类似方式计算出 EXPMA(10) 和 EXPMA(20) 的最新值，然后调用 `add_level` 将其加入到 `support_levels` 和 `resistance_levels` 中（权重可以设定为 0.9，介于 20日低点与近距离MA之间）。让更灵敏的 EXPMA 也能参与动态支撑和压力位的距离打分竞选。

2. **头部信息区**:
   - 保留 MA 均线和 ATR，去掉多余的调试提示、EXPMA、大盘模块等中间调试冗余。
2. **核心策略区**:
   - `📊 蓄势期 + 转弱 → 低吸高抛` 替代原有冗长的决策描述。
3. **📍 买卖点**:
   - 使用统一且对齐的列表，包含：止损价位、买入点及仓位、当前价位、卖出目标（带说明，如 1R 目标、保本等）、压力位、极端退出条件（如“阶段转派发 → 清仓”）。
4. **💡 为什么这么操作**:
   - 用最精简的自然语言总结“阶段”和“趋势”的核心支撑逻辑。
5. **📌 如果你有持仓**:
   - 包含当前状态及盈亏、反弹减仓点、止损认亏点。
6. **🔍 主力筹码 (新增搬家对比)**:
   - 现有的“筹码峰”正常展示。
   - **新增**“筹码变化（对比昨天）”模块：需要对比主要支撑/阻力筹码峰在昨日与今日的变化百分比（增减情况），并推导出一句话结论（如“底部筹码减少，顶部筹码增加，结论：筹码在搬家，主力在出货”或“主力在吸筹”等）。
7. **📊 五层打分 & 🎯 信号判断 & 亮点/风险**:
   - 按照样板的精简行文重新整合打分与亮点、警惕、风险等文字。不再输出详细的冗长信号明细（如融合层 JSON 输出）。

## 4. 边界范围
- 仅修改 `01-功能包-packages/trader` 相关输出模块（如 `02-共享模块-shared/trader_shared/output.py`、`report_formatter` 等渲染层代码，以及 `run_analysis.py` 里的 report 构建层）。
- 需确保筹码搬家的数据可以在系统快照历史中获取（昨天的数据通过 `chip_migration_monitor` 等类已有的 `save_chip_snapshot` 提供的数据实现）。
- 相应的 `output-template.md` 应当被更新以匹配最新契约。
