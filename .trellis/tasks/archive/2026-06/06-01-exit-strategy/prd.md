# 退出策略 — 聚焦两个问题

## 问题 1：Trader 显示格式

### 目标
从"报表系统"升级为"策略系统"，按阶段指导操作。

### 显示格式

```
分析报告 — 南网科技（688248）

现价：58.50元（-3.50%）
MA5：59.05｜MA10：60.58｜MA20：61.02｜MA30：59.85
ATR 3.69（6.1%）波幅偏高

📊 蓄势期 + 转弱 → 低吸高抛

📍 买卖点
  55.57 止损
  57.61 ← 买 10%（缩量企稳）
  58.50 当前
  59.22 → 卖 33%（阻力位）
  62.85 → 卖 33%（1R 目标）
  62.87 压力
  阶段转派发 → 清仓

💡 为什么这么操作
  阶段：蓄势期（区间震荡，低吸高抛）
  趋势：短期偏弱（价格在 59.00 下方），不追

📌 如果你有持仓（成本 60.00）
  现在：持有，不加仓（亏 2.5%）
  反弹到 60.00：减 50%（保本）
  跌破 55.57：止损（认亏）

🔍 主力筹码
  筹码峰：
    57.88（支撑）｜ 占比 5.91%
    60.46（强阻力）｜ 占比 6.99%
    63.05（弱阻力）｜ 占比 5.29%
  当前价以上：67.3%
  中位数价格：60.29

  筹码变化（对比昨天）：
    57.88（支撑）：5.91% → 4.50%（-24%）← 底部筹码减少
    60.46（强阻力）：6.99% → 8.50%（+22%）← 顶部筹码增加
    结论：筹码在搬家，主力在出货

📊 五层打分
  结构75/量价45｜筹码50｜动能50
  缠论：回调段。一类买、二类买
  威科夫：无明显威科夫信号

🎯 信号判断
  偏多：✓ 结构（两次接近位置止跌）
  警惕：! 量价（午后缩量）  ! 筹码（上方成交密集区）

✅ 亮点：58.50 仍站在防守位 57.61 上方
⚠️ 风险：筹码在搬家，主力在出货，警惕继续下跌
```

### 数据来源（全部真实，不编造）

```
✅ 价格：58.50（API 获取）
✅ MA：59.05/60.58/61.02/59.85（K 线计算）
✅ ATR：3.69（K 线计算）
✅ 阶段：蓄势期 + 转弱（数据判断）
✅ 买卖点：57.61/59.22/62.85（计算得出）
✅ 筹码峰：57.88/60.46/63.05（API 计算）
✅ 筹码占比：67.3%（API 计算）
✅ 筹码变化：-24%/+22%（历史数据对比）
✅ 五层打分：结构75/量价45/筹码50/动能50（数据计算）
✅ 信号判断：偏多/警惕（数据判断）
✅ 成本：60.00（用户输入 --cost）

❌ 不显示：大单买卖方向（推算的，不准）
❌ 不显示：筹码变化（没有历史数据时）
```

### 设计原则
- 阶段 → 操作 → 数据支撑
- 买卖点用价格流显示
- 主力筹码显示真实的筹码峰位置、占比、变化
- 不显示不真实的数据（大单买卖方向）
- 有历史数据时显示筹码变化，没有时显示"无历史数据"
- 成本来自用户输入（--cost），没有输入时不显示持仓建议

## 问题 2：筹码峰计算和筹码峰移动

### 目标
筹码峰数据必须精准，筹码变化必须有历史数据支撑。

### 一、筹码峰计算

#### 数据源
```
日线 K 线数据（从腾讯 API 获取）
字段：high, low, volume, close, turnover_rate（可选）
获取方式：data_provider.load_market_snapshot(target, days=120)
```

#### 计算方法（chip_distribution.py）
```
1. 自适应分箱
   价格范围：min(low) 到 max(high)
   分箱宽度：根据价格范围自动计算
   价格区间：每个区间代表一个价格水平

2. 成交量分配
   每天的成交量分配到价格区间：
     高价 → 40% 成交量（spread_weight）
     收盘价 → 60% 成交量（close_weight）
   分配方式：
     高价部分：均匀分配到 high-low 区间
     收盘价部分：集中分配到 close ± 2 个区间

3. 时间衰减
   换手率越高 → 旧筹码衰减越快
   衰减公式：volume_map = volume_map × (1 - decay_rate)
   decay_rate = max((turnover_rate / 100) ^ 0.5 × 0.3, 0.01)

4. 筹码峰检测
   找局部极大值（筹码集中的价格）
   去重：相邻峰间距 ≥ 4% 且 ≥ 4 个区间
   排序：按筹码占比降序
   输出：最多 3 个主峰 + 近价峰
```

#### 输出数据结构
```python
{
    "peaks": [
        {
            "price": 57.88,           # 筹码峰价格
            "volume": 1234567,         # 筹码量
            "share_of_total": 5.91,    # 占总筹码百分比
            "support_level": "支撑"    # 支撑/阻力判断
        },
        {
            "price": 60.46,
            "volume": 1456789,
            "share_of_total": 6.99,
            "support_level": "强阻力"
        }
    ],
    "total_volume": 20000000,          # 总筹码量
    "current_pct": 67.3,               # 当前价以上筹码占比
    "mid_price": 60.29,                # 筹码中位数价格
    "volume_above_pct": 67.3,          # 当前价以上筹码占比
    "bin_width": 0.5,                  # 分箱宽度
    "effective_range": (50.0, 70.0)    # 有效价格范围
}
```

### 二、筹码峰缓存

#### 缓存文件
```
路径：~/.trader/chip_history_{date}.json
示例：~/.trader/chip_history_2026-06-01.json
```

#### 缓存数据结构
```json
{
    "date": "2026-06-01",
    "target": "南网科技",
    "peaks": [
        {"price": 57.88, "share_of_total": 5.91, "support_level": "支撑"},
        {"price": 60.46, "share_of_total": 6.99, "support_level": "强阻力"},
        {"price": 63.05, "share_of_total": 5.29, "support_level": "弱阻力"}
    ],
    "volume_above_pct": 67.3,
    "mid_price": 60.29
}
```

#### 缓存时机
```
盘后复盘时：
  1. 调用 calc_chip_distribution() 计算当天筹码
  2. 存到 ~/.trader/chip_history_{date}.json
  3. 每天只存一次（盘后）
```

#### 缓存有效性
```
有效：当天有缓存文件
无效：没有当天缓存文件
过期：超过 1 天（自动重新计算）
```

### 三、筹码峰取数据

#### 盘中（trader/t0）
```
1. 检查缓存：~/.trader/chip_history_{today}.json
2. 如果有缓存：直接读缓存数据
3. 如果没有缓存：调用 calc_chip_distribution() 计算
4. 返回：当天的筹码峰数据
```

#### 盘后（review）
```
1. 调用 calc_chip_distribution() 计算当天筹码
2. 存到 ~/.trader/chip_history_{today}.json
3. 读昨天的缓存：~/.trader/chip_history_{yesterday}.json
4. 对比今天和昨天的数据
5. 计算筹码变化百分比
6. 返回：当天筹码峰 + 筹码变化
```

### 四、筹码峰显示

#### 显示格式（有历史数据时）
```
🔍 主力筹码
  筹码峰：
    57.88（支撑）｜ 占比 5.91%
    60.46（强阻力）｜ 占比 6.99%
    63.05（弱阻力）｜ 占比 5.29%
  当前价以上：67.3%
  中位数价格：60.29

  筹码变化（对比昨天）：
    57.88（支撑）：5.91% → 4.50%（-24%）← 底部筹码减少
    60.46（强阻力）：6.99% → 8.50%（+22%）← 顶部筹码增加
    结论：筹码在搬家，主力在出货
```

#### 显示格式（没有历史数据时）
```
🔍 主力筹码
  筹码峰：
    57.88（支撑）｜ 占比 5.91%
    60.46（强阻力）｜ 占比 6.99%
    63.05（弱阻力）｜ 占比 5.29%
  当前价以上：67.3%
  中位数价格：60.29

  筹码变化：无历史数据，无法计算变化
```

### 五、数据准确性要求

```
✅ 筹码峰位置：从 K 线计算，准确
✅ 筹码峰占比：从成交量计算，准确
✅ 当前价以上/以下占比：从价格区间计算，准确
✅ 筹码变化：有历史数据时准确，没有历史数据时显示"无历史数据"

❌ 不能编造数据
❌ 不能显示没有历史数据的筹码变化
```

## 实现步骤

### Step 1：筹码历史数据存储
- 盘后复盘时，调用 calc_chip_distribution() 计算当天筹码
- 存到 ~/.trader/chip_history_{date}.json
- 数据结构：date, target, peaks, volume_above_pct, mid_price

### Step 2：筹码变化计算
- 读昨天的 chip_history_{yesterday}.json
- 对比今天和昨天的 peaks 数据
- 计算每个筹码峰的变化百分比
- 返回：底部筹码变化、顶部筹码变化

### Step 3：显示格式
- 有历史数据时：显示筹码峰 + 筹码变化
- 没有历史数据时：显示筹码峰 + "无历史数据"
