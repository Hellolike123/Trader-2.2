## A. 数学矛盾（强一致性 bug，3 只票全中）

### A1. 筹码"中位数"与"当前价以上占比"数学矛盾 ⚠️ 必修

**现象**：三只票 100% 命中

| 票 | 现价 | 中位数 | 报告"当前价以上" | 数学预期 | 一致性 |
|----|------|--------|------------------|----------|--------|
| 江西铜业 | 47.33 | 47.12 | 53.0% | <50%（中位数<现价） | ✗ 矛盾 |
| 赣锋锂业 | 71.62 | 74.82 | 38.4% | >50%（中位数>现价） | ✗ 矛盾 |
| 三花智控 | 43.90 | 51.01 | 6.6% | >50%（中位数>现价） | ✗ 矛盾 |

**根因**：中位数的定义是"50% 筹码在此之下"。
- 中位数 < 现价 → 大部分筹码在现价下方（获利盘>50%）→ "当前价以上"（套牢盘）应 <50%
- 中位数 > 现价 → 大部分筹码在现价上方（套牢盘>50%）→ "当前价以上"应 >50%

实际报告三只票全部算反。

**修复**：检查 `chip_distribution.py` 中 `chip_current_pct` 的计算方向。可能是把"现价以下"误算成了"现价以上"，或中位数算反了。

### A2. 周线数据明明有，报告却说"无周线数据" ⚠️ 必修

**现象**：江西铜业报告 JSON 里 `weekly_close=53.31`（周线收盘价已抓到），但 resonance 模块输出"日线代理多头（站上）（无周线数据）"。

```

resonance.weekly_label: "日线代理多头（站上）（无周线数据）"  ← 却说无数据
```

**根因**：`multi_timeframe_resonance.py` 没去用 `weekly_close` 字段，而是另起一路抓周K，抓失败就退回"日线代理"。

**修复**：resonance 模块直接复用已抓到的 `weekly_close` / `monthly_close`，不要再走独立抓包通道。

### A3. 月线数据 43.47 比周线 53.31 低 18%，数据本身错误 ⚠️ 必修

月线收盘价不可能比同一时刻的周线收盘价低 18%。要么月线数据是过期/错误抓取，要么字段映射错了。

**修复**：检查 `light_data.py` 中月线数据抓取逻辑，确认 `monthly_close` 字段来源。

### A4. EXPMA deviation 满分 3/3，但当日 -4.13% ⚠️ 必修

**现象**：江西铜业 EXPMA 评分明细：

```
deviation_score: 3  ← 满分
total_score: 9/10
trend_label: 多头排列（强势）
当日涨跌: -4.13%
现价 47.33 vs EXPMA5 48.59 → 现价在 EXPMA5 下方 2.6%
```

**问题**：deviation（偏离）评分应该衡量"价格对 EXPMA 的偏离程度"。当日 -4.13%、现价远离 EXPMA5 向下，应该扣分而不是满分。

**根因**：`expma_score.py`（或同名模块）的 deviation_score 只看 EXPMA 之间的排列，不看现价与 EXPMA 的关系。

**修复**：deviation_score 增加"现价 vs EXPMA5 距离"维度：
- 现价 > EXPMA5 × 1.02：满分（强势偏离）
- 现价在 EXPMA5 ±2%：中性
- 现价 < EXPMA5 × 0.98：扣分（弱势偏离）

## C. 严重 bug（命令直接挂掉或逻辑断裂）

### C1. portfolio 命令 100% 失败 ⚠️ P0 必修

**现象**：

```bash
$ python3 trader.py portfolio --targets 江西铜业 赣锋锂业
输出校验失败：
single review must start with 盘后复盘/午间复盘 — 名称（代码）
missing five-layer theory line: 缠论
missing five-layer theory line: 威科夫
```

**根因**（已定位代码）：

`01-功能包-packages/review/scripts/final_portfolio.py` 第 10 行：

```python
from validate_output import validate
```

而 `review/scripts/validate_output.py` 第 11 行：

```python
from trader_shared.schema.v1 import validate_review
validate = validate_review   # ← 别名指向了 review 校验器！
```

所以 portfolio 输出被拿去用 review 的规则校验，必然失败。

**修复**：`final_portfolio.py` 改为直接 `from trader_shared.schema.v1 import validate_portfolio as validate`。

### D1. 赣锋锂业当日 +5.32% 大阳线，结构评 -50 "三类卖" ⚠️ 必修

**现象**：赣锋锂业当日 +5.32%（大阳线），但五层打分：

```
缠论：缠论三类卖 (跌破中枢)
```

**问题**：涨停股评"三类卖"是滞后信号，但报告同时给"试探买 10%"建议——一边说三类卖一边说买，操盘手无所适从。

**修复**：当缠论三类卖 + 当日涨幅 > 3% 时，应在结构分上增加"反转修正"加分，并在文案中说明"原三类卖信号已被今日大阳线否定"。

### D2. 三花智控 EXPMA 3/10 偏空 + 三类卖，但"试探买 5% 缩量企稳" ⚠️ 必修

**现象**：三花智控：

```
📍 买卖点：42.70 ← 试探买 5%（缩量企稳）
```

**问题**：EXPMA 偏空 + 三类卖 = 看空信号叠加，却给"试探买 5%"建议——方向自相矛盾。

### D3. 三花智控"高抛区间 47.94-48.86" 下限高于现价 9.2%，但融合说"减 1/3 高位松动" ⚠️ 必修

```
融合｜⚪ 减1/3 (高位松动)
📍 买卖点
  高抛区间 47.94-48.86元    ← 下限高于现价 9.2%
```

**问题**：融合说"现在就减 1/3"，买卖点说"47.94 才高抛"——一个说现在减，一个说等涨 9% 才减，互相打脸。

**修复**：高抛区间下限 = `max(阻力位, 现价 × 1.02)`，确保下限始终 ≥ 现价。

### D4. "试探买 71.60" vs 现价 71.62，差 0.02 元（0.03%）⚠️ 必修

**现象**：赣锋锂业：

```

```

**问题**：试探买价和现价差 0.03%——等于"现价买入"叫"试探买"。"试探"的意义是"在比现价低的位置挂单等回踩"，不是"现价买入"。

**修复**：试探买价 = `min(支撑位, 现价 × 0.98)`，与现价至少差 1.5%（基于 ATR）。

### D5. 所有票无论涨跌都叫"缩量企稳" ⚠️ 必修

**现象**：三只票的试探买标签：

| 票 | 当日涨跌 | 试探买标签 |
|----|---------|----------|
| 江西铜业 | -4.13% | 缩量企稳 |
| 三花智控 | +1.64% | 缩量企稳 |
| 赣锋锂业 | +5.32% | 缩量企稳 |

**问题**：跌 4% 叫企稳、涨 5% 也叫企稳——标签写死，没信息量。

- 当日 ±1% 内 + 缩量：`横盘缩量`
- 当日放量：`放量企稳`（无论涨跌）
