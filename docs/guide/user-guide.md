## 每日工作流

```
盘前（9:30 前）
  看作战表 → 知道今天盯哪几只

盘中（9:30-15:00）
  验票 → 中线能不能跟、短线追不追
  盯盘 → 价格到位 / 大单异动告警

盘后（15:00 后）
  复盘 → 今天表现怎么样
  信号统计 → 系统准不准
```

- meta 一行对照：板块指数（科创/创业板/上证/深成）｜行业｜个股；不写「正常/偏弱」，自己从涨跌看强弱

## 五、关键规则速查

### 5.1 四阶段仓位

```
蓄势期：0-30%（试探）
主升期：50-80%（重仓）
派发期：0-30%（减仓）
衰退期：0%（空仓）

硬规则：持仓亏损时，禁止加仓
```

### 5.2 入池规则

```
衰退期 → 拒绝入池
蓄势期 + 评分 ≥ 70 → 观察
蓄势期 + 评分 ≥ 80 → 执行
主升期 + 评分 ≥ 60 → 执行
派发期 + 评分 ≥ 70 → 观察
```

### 5.3 轮动规则

```
主升期 → 不轮（让利润跑）
派发期 → 看技术指标决定轮多少
衰退期 → 必须清仓
蓄势期 → 看技术指标
```

### 5.4 缓存规则

```
盘中：实时行情抓最新，历史数据用缓存
盘后：所有数据用缓存
t0：不缓存，每次都抓最新
```

## 六、防止 Hermes 乱改格式

### 6.1 问题

Hermes 可能会出现以下情况：
- 看到脚本输出，觉得「格式不好看」，自己改
- 觉得「信息不够」，自己加内容
- 觉得「应该用 markdown」，自己加标题/表格/粗体

### 6.2 解决方案

在 SKILL.md 里写死以下规则：

```
⚠️ 输出红线（绝对禁止违反）

1. 脚本输出的文本是最终格式，不要修改任何内容
2. 不要添加脚本输出以外的解释、建议或总结
3. 不要用 ##/### 标题、**粗体**、|表格|、>引用、- 列表
4. 输出后必须跑 validate_output.py 校验
5. 校验不通过 → 重新跑脚本，不要自己修格式
6. 如果用户问格式相关问题，直接引用 output-template.md 和 output-style-guide.md

验证命令：
  python3 scripts/validate_output.py
  → 返回 VALID_TRADER_OUTPUT=OK 才算通过
  → 返回错误信息 → 重新跑脚本
```

### 6.3 输出流程

```
脚本生成输出
     ↓
自动跑 validate_output.py
     ↓
通过 → 发给用户
     ↓
不通过 → 重新跑脚本（不要自己修）
```

### 6.4 各 Skill 校验命令


### 6.5 如果 Hermes 还是乱改

## 附录：核心技术指标解析（EXPMA 战法）

EXPMA（指数移动平均线）是本系统判断趋势与止损的核心工具之一。作为一种加权均线，它对最近价格赋予更高权重，比普通均线（MA）反应更快。

### 1. 系统参数设置与映射
系统底层（`config.py`）严格遵循了以下经典参数配置：
* **EXPMA(10)**（短线趋势）：用于主升浪的动态跟踪。只要价格站上 EXPMA(10)，系统判定为强势，给予额外加分并提示“拿着”。
* **EXPMA(12) / EXPMA(50)**（趋势判断）：用于判断中线多空（类似于金叉/死叉逻辑过滤）。
* **EXPMA(20)**（中短期防守）：在派发期，系统会优先将退守防线从 MA20 切换为反应更快的 EXPMA(20)。

### 2. 常见用法（已集成入四阶段模型）
* **动态支撑与多头跟踪**：强势上涨（主升期）过程中，回调到 EXPMA(10) 附近获得支撑后继续上涨，系统会触发低吸或加仓。
* **破位减仓（死叉/跌破）**：一旦收盘价跌破 EXPMA(10)，系统将自动触发“趋势转弱”信号，并在作战表中提示“跌破防线，减仓”。
* **多头排列确认**：在判定“走强”或“修复”状态时，系统会综合考察短期 EXPMA 与中期 EXPMA 的相对位置，过滤掉短期噪音。

（注：本系统在 A 股日线交易中，结合缠论结构与 HMM 状态机，EXPMA 被用作极其关键的辅助验证和动态止损线。）
