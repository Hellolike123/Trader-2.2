# Skill 合并方案

## 背景

当前 6 个 skill 存在以下问题：
- 骨架重复（6 套 SKILL.md / HERMES.md / commands.md / output-contract.md）
- 紧耦合（pool 直接 import trader 的 run_analysis）
- 边界模糊（pool 和 trader 都有 run_analysis.py）
- 80% 的提交是跨 skill 的，改一个功能要同步多个目录
- 维护成本高，使用记不住

## 决策：6 合 3

```
原 6 个 skill                    合并后 3 个
─────────────                   ──────────────
01-单票分析-trader        ──┐
03-选股池-trader-pool     ──┼──▶  trader（分析+选票）
                            │
02-盘中T0-t0-trader       ──┼──▶  t0（盘中盯盘）
                            │
04-仓位轮动-trader-portfolio──┤
05-盘后复盘-review-trader  ──┼──▶  review（盘后复盘+仓位+追踪）
06-信号追踪-trader-tracking──┘
```

扩展数据（股东/机构/解禁/题材）从 trader 中移除，未来单独做 funda skill。

## 各 Skill 职责

### trader（分析+选票）

职责：纯技术分析 + 选股池管理
- 单票分析报告（原 01-trader，去掉扩展数据）
- 选股池入池/出池/排序/作战表（原 03-pool）
- 买 zone + 止损计算
- 四阶段定位（大阶段 + 短期动能嵌套）

命令映射：
- `trader script --target <NAME>` → 单票分析
- `trader script add --target <NAME>` → 入池
- `trader script rank` → 池内排序
- `trader script plan` → 作战表
- `trader script remove --target <NAME>` → 出池

### t0（盘中盯盘）

职责：实时监控 + 告警（只负责「看」和「响」）
- 盘中大单异动扫描（原 02-t0）
- 价格到位告警
- 读 trader 的 pool.json 知道盯哪几只
- 触发后写 signals.jsonl

命令映射：
- `t0 script --target <NAME>` → 单次检查
- `t0 script --target <NAME> --monitor` → 持续监控
- `t0 script --target <NAME> --monitor --once` → 定时任务单次

### review（盘后复盘+仓位+追踪）

职责：盘后复盘 + 仓位轮动 + 信号统计分析
- 五层打分复盘（原 05-review）
- 仓位轮动（原 04-portfolio）
- 信号统计分析（原 06-tracking，重新设计）

命令映射：
- `review script --target <NAME>` → 单票复盘
- `review script --targets A B` → 仓位轮动
- `review script --tracking` → 信号统计分析

## 核心设计决策

### 1. 250日线一票否决不屏蔽，只提醒

250日线是筛选条件，但不屏蔽分析内容。用户可能在下跌市中找抄底机会。

```
分析报告 — 某某票（000000）

⚠️ 250日线下方，一票否决，建议不参与
（以下供参考，如有看好的票可忽略此提醒）

现价：xx.xx元（+x.xx%）
...（完整分析照常显示）
```

### 2. 四阶段定位（大阶段 + 短期动能嵌套）

两层嵌套模型：
- 第一层：大阶段（蓄势/主升/派发/衰退）→ 长期周期位置
- 第二层：短期动能（走强/修复/震荡/转弱）→ 最近在干嘛

组合决策：
```
              短期动能
              走强    修复    震荡    转弱
大阶段
──────────────────────────────────────────
蓄势          试探买   观察    等待    不碰
              (10%)   (0%)   (0%)   (0%)

主升          加仓    持有    持有    减仓
              (70%)   (50%)  (50%)  (30%)

派发          减仓    减仓    减仓    清仓
              (30%)   (20%)  (20%)  (0%)

衰退          不碰    不碰    不碰    不碰
              (0%)    (0%)   (0%)   (0%)
```

### 3. 仓位跟着大阶段走

仓位不再只看 ATR 波幅，而是先看大阶段：
- 蓄势期：0-30%（试探）
- 主升期：50-80%（重仓）
- 派发期：0-30%（减仓）
- 衰退期：0%（空仓）

ATR 变成「在阶段范围内微调」的工具。

### 4. 大盘显示阶段判断

```
🌍 大盘
中证1000｜大阶段：衰退期｜今日跌1.3%
```

大盘阶段 + 个股阶段 = 双重过滤。

### 5. T0 参考保留

用户在蓄势期会做 T0，所以 trader 输出里保留 T0 参考：
```
T0 参考
  低吸：57.50 ｜ 高抛：62.69 ｜ 止损：56.11
```

### 6. 信号统计纯数字，不给建议

定位：「信号说买→涨了吗？信号说卖→跌了吗？」

不给建议，只给数字，用户自己判断。

## 性能优化

### 1. 去掉扩展数据（省 7 秒）

扩展数据（股东/机构/解禁/题材）从 trader 中移除。这些是基本面数据，不属于技术分析。未来单独做 funda skill。

优化前后对比：
```
数据抓取      0.7s
扩展数据      7.0s  →  0（去掉）
分析模块      1.8s
──────────────────
总计：9.5s  →  2.5s
```

### 2. 预缓存（省 0.7 秒）

交易日下午 15 点自动预缓存选股池全量数据。

命令：
- `trader.py cache warm` → 预缓存
- `trader.py cache clear` → 清缓存
- `trader.py cache clear --type daily` → 只清日线缓存

缓存规则：
- trader（分析）：日线K线可以缓存，实时行情盘中抓最新、盘后用缓存
- t0（盯盘）：不缓存，每次都抓最新实时数据
- review（复盘）：日线K线和大单回溯可以缓存（盘后数据不会变）

```
                盘中（9:30-15:00）    盘后/周末
──────────────────────────────────────────────────
trader 日线K线    用缓存               用缓存
trader 实时行情   抓最新               用缓存
t0 实时行情       抓最新               不运行
review 日线K线    用缓存               用缓存
```

一句话：实时数据盘中都抓最新的，历史数据都用缓存。

自动清理策略：
- 交易日 15:00 清日线缓存 + 预缓存新数据
- quote TTL 5 分钟（自然过期）
- 非交易日不清（周末保持缓存）

预缓存后数据抓取也变 0：
```
数据抓取    0s（缓存命中）
分析模块    1.3s（并行后）
──────────────────
总计：1.3 秒
```

### 3. 分析模块并行化（省 0.5 秒）

chanlun/wyckoff/momentum 三个策略模块并行运行。

```
现在（串行）                  并行后
chanlun_strategy   0.5s      ┐
wyckoff_strategy   0.3s      ├─ 并行  0.5s
momentum_strategy  0.2s      ┘
fusion_core        0.3s      fusion_core        0.3s
structure_core     0.5s      structure_core     0.5s
总计：1.8s                    总计：1.3s
```
